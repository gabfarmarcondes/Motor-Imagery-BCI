**Neuro-Control** is an active Brain-Computer Interface (BCI) project designed to translate real-time neural signals into digital commands.

Unlike passive monitoring systems, this project focuses on **Motor Imagery (MI)**: detecting the user's intention to move (e.g., Left Hand vs. Right Hand) solely through EEG signals, enabling hands-free control of applications and games.

## 🎯 Objective
Build a low-latency pipeline to classify 4-class Motor Imagery signals using **Common Spatial Patterns (CSP)** and Deep Learning (**EEGNet**) to control a game environment (Pong/Minecraft).

## 📂 Dataset
**BCI Competition IV 2a** (Graz University)
- **Signals:** 22 EEG channels (10-20 system) + 3 EOG channels.
- **Tasks:** Left Hand, Right Hand, Feet, Tongue.
- **Sampling:** 250 Hz.

## 🛠 Tech Stack
- **Acquisition & Processing:** `MNE-Python`, `NumPy`, `SciPy`
- **Machine Learning:** `PyTorch` (EEGNet), `Scikit-Learn` (LDA)
- **DevOps:** `Docker`
- **Interface:** `PyGame` (Planned)

## Evaluation Protocol

All results in this project (CSP+LDA baseline and EEGNet) are computed via
leave-one-run-out cross-validation within each subject's **training session**
("T" files, `A0{subject}T.gdf`). The BCI Competition IV 2a **evaluation session**
("E" files, `A0{subject}E.gdf`) is not used for any reported result, because those
files ship without class labels (historically released only after the original
2008 competition deadline).

This means there is no fully independent held-out test set in the traditional
sense, every number in `results/` comes from cross-validation folds within the
same recording session. This is a known limitation, not an oversight: it should
be kept in mind when comparing these results to published work that does have
access to session E labels.
